## Result and fixed scope

Move issue resumed-at from Store into the issue continuation component. Preserve current timestamp-equality identity; capture the chosen reply/body/branch inputs and consume that exact reply with successful resume reservation. Reuse the existing command/run rail for crash continuation. Add the field parser and shadow comparison to C3. Migrate the no-PR issue resume/fork count and remembered branch selection in this same admission, reusing existing resolve workspace/handoff authority; refusal changes none of them. Preserve fresh-reply construction without a session and author-tests-split routing. A blank reply has the existing unpaid consumption path: commit a no-op consumption receipt plus the durable issue re-block projection intent, with no reservation.

## Acceptance

- [x] The same observed timestamp cannot purchase twice under repeated polls, competing admission or restart.
- [x] A budget/owner refusal consumes nothing; an admitted crash cannot silently purchase a fresh duplicate.
- [x] Reordered observations cannot erase a later consumption marker; distinct newer replies retain current eligibility rules.
- [x] Malformed/ambiguous import blocks; unrelated holds and resolve allowance survive.
- [x] Blank issue reply consumes once without a paid call and recovers its re-block projection; absent-session fresh reply and author-tests-split resume still work. Refusal preserves the issue fork count/branch and leaves a nonblank reply available.

## Removal obligation

Remove runtime issue get_resumed_at/set_resumed_at use; retain importer only. Retire no-PR resume bump_resumes and remembered branch file authority after all selected callers use the same fixed component.

## Out of scope

Do not introduce comment-ID migration or the separate authenticated-channel feature from issue #184.
