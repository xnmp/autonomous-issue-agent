# [Phase 4 C1] Add fixed continuation component contracts without a new workflow engine

Published: [#215](https://github.com/xnmp/autonomous-issue-agent/issues/215). Accepted locally in `c8aa2e6`.
Parent: [tracking epic #199](https://github.com/xnmp/autonomous-issue-agent/issues/199). Outcome gate: **4**.

**Blocked by:** [R8 · #214](https://github.com/xnmp/autonomous-issue-agent/issues/214)

## Result and fixed scope

Add explicit fixed variants for issue reply/recovery, PR repair/reply/recovery and issue steward continuity. Each selected component carries the shared target fence and independent family epoch/episode, activation/blocked state and ordered admission watermark. Use typed inactive/blocked/active variants, not an extensible registry. Define an inert issue workflow shell for stewardship before resolve activation; it grants no resolve episode or allowance.

## Acceptance

- [x] Typed issue and PR components cannot alias, invent active authority from absent state or discard sibling components on primary transitions.
- [x] A stewardship-only issue exists with no resolve authority; an ordinary resolve reader returns migration-required until real activation.
- [x] Generation carry preserves unrelated component allowances and gates; old component outcomes cannot overwrite newer continuity.
- [x] Existing resolve/rejection snapshots and bindings retain their accepted semantics.

## Removal obligation

Remove the assumption that selecting any component can be inferred solely from target_family(); keep it as the existing primary-family selector.

## Out of scope

Coordinator owns this shared contract. Sol implements the fixed design; do not add plugin registries, generic state machines or extra queues.
