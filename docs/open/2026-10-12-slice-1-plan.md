# Slice 1: delete review-time operator tests

Part of [the minimal harness design](2026-10-12-minimal-harness-design.md). The daemons are off.

## Why
The reviewer runs `TEST_CMD` on the PR head and requires a stored receipt before it approves. That duplicates CI on a loaded shared host. Its load flakes became rejections and holds (#1068 ×4, #1084, #1088, #999, #1001, #320 ENOSPC), and it added episodes, backoff, renewals, synthetic verdict holds and a waiver (added 2026-10-05, 0294b3e, +841 lines). The one gap it closed, an agent editing CI workflows, gets a narrow governance rule instead.

## After this slice
- **The reviewer approves on its model verdict for the exact head.** Merge still requires the repo's required checks (#319, unchanged).
- **A PR whose diff touches `.github/workflows/**` is escalated to a human** through the existing ESCALATE path, since CI config is repo governance. This is the slice's only addition, about 10 lines.
- **No review leg runs target tests.** Nothing stores, waits on, backs off on, renews or releases test evidence.

## Delete
- `domain/review_test_evidence.py` and `adapters/review_test_execution.py`, whole files.
- **The test-receipt plumbing:** receipt persistence and its SQL in `control_store`, the durable-writer validation that requires a receipt before an approval, and the conversion in `app/review_runtime.py` (approve + failed tests → REQUEST_CHANGES).
- **The holds and actions that exist only for tests:**
  - ordinary-test holds and the renew-execution path for them;
  - test-only release receipts in `_fixed_verdict_receipt`;
  - the synthetic verdict-hold path for test rejections.
- **Config:** `ALLOW_UNTESTED`, and review-side use of `GATE_TEST_FAILURE_EXIT_CODES` and `TEST_CMD`. Keep both if the fixer gate still reads them; that gate goes in slice 6.
- **Wire and dashboard fields** for test evidence and test holds.
- **Docs:** the ADR 0011 receipt paragraphs, the HARNESS.md "Renew execution" text, and the architecture manifest rows.
- **Tests that only pin deleted behaviour:** delete them; do not port them.

## Keep (other slices)
- Review execution episodes and `ReviewExecutionCeiling` *as they count review-leg deaths* (slices 3 and 5). Delete only their test-evidence use.
- The fixer's TDD gate and governor (slice 6).
- The CI required-checks gate.

## Data
- Add one schema migration that drops the test-receipt tables.
- Persisted gates or holds whose cause is test evidence must load as absent, with no crash and no migration block. A PR held only by one simply proceeds next tick.
- Cutover is drop-and-re-derive; nothing is preserved for compatibility.

## Acceptance
1. `make test` is green on a quiet host, and `make typecheck` is clean.
2. Net `src/` lines are negative; target −1,000 or more. No new counter, hold, label, knob or state.
3. Behavioural tests:
   - approve with no test execution, then merge gated on required checks;
   - red required checks → no merge;
   - a workflow-touching PR → escalation;
   - a DB holding legacy test receipts and holds loads cleanly, and the PR proceeds.
4. No source or doc references remain to the deleted symbols, beyond the migration that drops the tables.
5. An unbiased adversarial review returns SHIP, then the PR merges to `dev`.

## Execution
Codex xhigh implements this in a worktree off `origin/dev`, running focused tests only. Then: a fresh unseeded Codex review, a full suite once the quiet-host check passes, a PR, and an admin merge on green CI.
